# 禹泽项目安全与测试报告

## 结论与范围

以《禹泽数字科技小程序会员消费增值与六星店长白酒专卖需求文档》V1.1为业务基准。本轮已修复msgSecCheck代理及个人昵称链路的确定性漏洞；**不是全项目安全整改完成，不建议当前版本直接上线处理真实资金**。广域审查发现的财务、订单、退款、找回密码缺陷仍未修复，不能把48项测试通过理解为资金安全证明。

本轮未改变雨点折算、咯哒权益、白酒交易结算政策；待甲方确认Q1~Q17，不能以旧代码默认算法替代需求。

所有项目运行/测试在WSL Linux隔离副本中进行。最初WSL PATH内uv符号链接指向Windows uv.exe，安装命令未找到Linux路径下项目；随后改为临时目录原生Linux uv 0.9.8。未用Windows Python运行项目。

- Python：WSL原生CPython 3.14.7；项目声明>=3.13。

- 实际HTTP：在WSL本机随机端口启动真实`main:app`，禁用startup lifespan（避免迁移/定时任务），以合成身份替换认证数据源、httpx.MockTransport替换微信网络端。实际运行代理请求构造、v2结果判定、HTTP序列化、业务拒绝及OpenAPI生成。

## 与主需求的业务冲突和设计风险

1. 旧月结方案按330/30、月末有效，V1.1要求每日折算与30天有效；不能原样联调就宣称FR-203完成。
2. 月结筛选`users.status=1`，认证语义1为冻结、0为正常，可能向冻结用户发券而漏掉正常会员。
3. 日补贴扣member_points、月结券到期进入director_pool，与长期积分及补贴池需求不一致。
4. 配置reward_points可能让全券普通商品仍产生积分，与FR-204冲突。
5. 咯哒蛋恒量、80/20池分流、100%自动转化、白酒合同唯一权属与80/20结算缺完整实现；业务接口文档将目标设计与可调用现状分开。
6. 需求初始“1券=100蛋”与80%兑换公式示例不一致；100券→8000蛋遵循明确计算示例，但仍需甲方澄清文案。
7. Q1~Q17涉及算法、池体定义、并发、退款回退、财务应付、等级、物流、数据保留，未书面确认不得硬编码资金政策。
8. 专用文本审核限流缺失，认证账户仍可能消耗微信额度；review暂无人工复核工作流。
9. 导入/注册有数据库与线程副作用；单元测试隔离和运维启动易被外部依赖影响。
10. 金额单位混用元/分、Decimal转float、部分响应模型宽泛、大分页上限，需业务边界与性能回归；这些为风险，不宣称本轮已证明实际资金精度损失或DoS。
