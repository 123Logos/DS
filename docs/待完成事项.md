## V1.1 严重级漏洞修复（分支 fix/v1-rights-migration-atomicity）的上线前置

上线顺序不可颠倒，否则旧账本与新账本会重新分叉：

1. `uv run python scripts/migrate.py` —— 执行 `007_v1_rights.sql` 建表，再执行 `008_legacy_assets_bridge.sql` 安装镜像触发器；
2. `uv run python scripts/migrate_legacy_assets.py --check-triggers` —— 把历史 `users.member_points` / `users.true_total_points` 灌入 `user_assets`，并输出迁移前后对账（必须 `是否完全对齐 = 是`，退出码 0）；
3. 服务侧确认 `core/scheduler.py` 中 `v1_global_auto_conversion`（每分钟）与 `v1_daily_rights_settlement`（每日 00:00）已注册，且旧 `daily_subsidy_auto` / `monthly_rain_point_coupon` 保持停用。

**加锁顺序（全库唯一，违反即死锁）**

```
system_pools  →  users  →  user_assets  →  业务表（wine_jars / wine_listings / rights_coupon_batches）
```

- `users` 这一步**不可省略**：镜像触发器 `trg_users_assets_mirror_update` 的执行路径是 users → user_assets，旧业务（下单扣积分、退款、旧券核销）天然同向。新代码若只锁 `user_assets`，一旦事务内再回头碰 `users` 就与旧业务形成环路。
- 代码入口：`RightsService.lock_pools()` / `lock_legacy_user()` / `lock_user_assets()`（依次为第 1/2/3 步）；`services/legacy_assets_bridge.py::lock_legacy_user` 是同一件事的桥接版本。
